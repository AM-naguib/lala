# Screen UX Checklist

> تُطبق على كل Screen قبل Delivered. البنود P0 إلزامية ولا يجوز تأجيلها.

## A. المهمة والسياق

- [ ] **P0** المهمة الأساسية مكتوبة في جملة واحدة.
- [ ] **P0** المستخدم المستهدف وصلاحياته معروفان.
- [ ] **P0** للشاشة Entry point واضح من شاشة حالية.
- [ ] **P0** يوجد Exit أو Back destination مفهوم.
- [ ] **P1** المهام الثانوية لا تنافس المهمة الأساسية.

## B. التنقل ومعرفة المكان

- [ ] **P0** Parent الصحيح ظاهر Active في Desktop وMobile.
- [ ] **P0** يوجد `aria-current="page"` على الوجهة الحالية.
- [ ] **P0** لا توجد Dead links أو شاشة يتيمة.
- [ ] **P0** العنوان وBreadcrumb واسم القائمة يستخدمون نفس المصطلح.
- [ ] **P1** الـTabs تستخدم لصفحات متساوية داخل نفس المجموعة فقط.
- [ ] **P1** المستخدم يصل للمهمة خلال مستويين بحد أقصى.

## C. الإجراءات

- [ ] **P0** يوجد Primary action واحد واضح.
- [ ] **P0** الأزرار تصف النتيجة: “استرجاع كمخفي” أفضل من “تأكيد”.
- [ ] **P0** الإجراء المدمر يعرض Preview لما سيتغير.
- [ ] **P0** يوضح النظام إمكانية التراجع أو الاسترجاع والحالة الناتجة.
- [ ] **P1** الإجراءات النادرة داخل More actions أو قائمة ثانوية.
- [ ] **P1** الإجراء Disabled يشرح السبب وطريقة التفعيل.

## D. النماذج

- [ ] **P0** كل Field له Label ظاهر، وليس Placeholder فقط.
- [ ] **P0** المطلوب والاختياري واضحان قبل Submit.
- [ ] **P0** Validation بجوار الحقل وبصياغة قابلة للتنفيذ.
- [ ] **P0** إدخال الأرقام والهاتف والأسعار وSKU يحافظ على اتجاه LTR وMono.
- [ ] **P1** القيم الافتراضية لا تبدو كقرار اتخذه المستخدم.
- [ ] **P1** الخروج مع تغييرات غير محفوظة له Warning مناسب.

## E. الجداول والقوائم

- [ ] **P0** الصف 52px والخلايا 12×16px والنص 14/20.
- [ ] **P0** الأعمدة مرتبة حسب أهمية مهمة المستخدم.
- [ ] **P0** حالات Empty وNo results مختلفة في الرسالة والإجراء.
- [ ] **P0** Bulk actions توضح عدد العناصر وتأثير الإجراء.
- [ ] **P1** الفلاتر قابلة للمسح والنتيجة توضح عدد العناصر.
- [ ] **P1** الموبايل يستخدم Cards أو Scroll مقصودًا مع بقاء أهم البيانات أولًا.

## F. التغذية الراجعة والتعافي

- [ ] **P0** Loading لا يوحي أن النظام متوقف.
- [ ] **P0** Success يوضح ما تم وما الخطوة التالية.
- [ ] **P0** Error يوضح ما فشل وما الذي لم يتغير.
- [ ] **P0** Retry آمن ولا يكرر العملية دون قصد.
- [ ] **P0** Background process يسمح بمغادرة الشاشة والعثور على النتيجة لاحقًا.
- [ ] **P1** Toasts لا تحمل معلومات لا يمكن استعادتها بعد اختفائها.

## G. العربية والإنجليزية

- [ ] **P0** النص العربي حقيقي ومراجع وليس ترجمة حرفية آلية.
- [ ] **P0** RTL وLTR يغيران الاتجاه فعليًا.
- [ ] **P0** العناوين والأزرار والـPills لا تُقص في العربية.
- [ ] **P0** Mono داخل العربية مضبوط Baseline واتجاهه LTR.
- [ ] **P1** المصطلح ثابت عبر كل الشاشات والوثائق.

## H. الوصول والموبايل

- [ ] **P0** كل Control له اسم Accessible.
- [ ] **P0** Focus ظاهر وترتيب Keyboard منطقي.
- [ ] **P0** Touch targets مناسبة ولا تعتمد على Hover.
- [ ] **P0** التنقل الرئيسي متاح على الموبايل.
- [ ] **P1** Dialogs لها Title وClose وFocus behavior واضحان في التنفيذ النهائي.
- [ ] **P1** اللون ليس الإشارة الوحيدة للحالة.

## I. البيانات الحساسة

- [ ] **P0** Wallet overdraft يخفي الهاتف والبريد والعنوان وأي PII مطلوب.
- [ ] **P0** البيانات غير الحساسة اللازمة لفهم الطلب تبقى ظاهرة.
- [ ] **P0** Export الحساس Disabled أثناء masking.
- [ ] **P0** Banner يشرح سبب الإخفاء وكيف يعود الوصول.

## نتيجة المراجعة

| النتيجة | المعنى |
|---|---|
| Pass | كل P0 ناجحة ولا توجد مشكلة تمنع المهمة |
| Pass with backlog | كل P0 ناجحة، ومشكلات P1/P2 مسجلة بمالك وBatch |
| Fail | بند P0 فشل؛ لا تُسلم الشاشة حتى الإصلاح |
